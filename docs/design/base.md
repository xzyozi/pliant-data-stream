# 基本設計書：環境非依存型 CSV/TSV データ処理エンジン

## 1. システム概要・目的

本システムは、サードパーティ製ライブラリ（PandasやPolars等）に一切依存せず、Python標準機能のみを用いて構築される高可搬なデータ処理・ソートエンジンである。
数GBを超える巨大なCSV/TSVファイルを、メモリを枯渇させることなく（OOM回避）高速にパース・抽出・ソートし、結果のファイル出力やSQLiteデータベースへの永続化を行うことを目的とする。

## 2. システム方式設計（パイプライン・アーキテクチャ）

巨大ファイルを扱うため、全データを一度にメモリに読み込む方式（オンメモリ方式）は採用せず、ストリーム処理と分割処理を組み合わせたパイプライン方式を採用する。

1. **リーダー層:** ファイルをストリームとして行単位で読み込み、区切り文字を自動判定。
2. **フィルタ層:** ソート不要なデータの除外（Grep）や重複排除（Unique）をストリーム上で実行し、処理対象を最小化。
3. **分割・一時ソート層:** データを一定行数（例: 10万行）のチャンクに分割し、メモリ上でソート後、一時ファイルとしてディスクに退避（Spilling）。
4. **マージ層:** 複数の一時ファイルを並行して読み込み、ストリーム上で統合ソート（K-wayマージ）を実行。
5. **ライター・永続化層:** 最終結果をCSV/TSVとして書き出すか、SQLiteにINSERTして永続化。

## 3. 機能要件定義

### 3.1 I/Oおよびパース機能

| 機能名 | 処理内容 | 適用標準モジュール |
| --- | --- | --- |
| **フォーマット自動判定** | カンマ区切り、タブ区切りを自動判定し、適切に分割する。 | `csv.Sniffer` |
| **セキュアパース** | ダブルクオート内の改行やデリミタを破壊せずにパースする。 | `csv.reader`, `csv.writer` |
| **自動型推論** | 文字列、整数、浮動小数点、日付を推論し、適切な比較演算を適用する。 | `datetime`, 組み込み型 (`int`, `float`) |

### 3.2 データクレンジング・抽出機能（Grep / Unique）

| 機能名 | 処理内容 | 適用標準モジュール |
| --- | --- | --- |
| **正規表現フィルタ (Grep)** | 指定カラムに対し、コンパイル済みの正規表現でマッチングを行い、非該当行を破棄する。 | `re` |
| **重複排除 (Unique)** | 指定されたキー（複数カラム可）のハッシュ値を保持し、既出の行をスキップする。 | `hashlib`, `set` |
| **欠損値制御** | 空文字列を検知し、ソート時に先頭または末尾に強制配置する。 | カスタム比較関数 |

### 3.3 コアソート機能（外部マージソート）

| 機能名 | 処理内容 | 適用標準モジュール |
| --- | --- | --- |
| **チャンク分割・退避** | メモリ上限に合わせてデータを分割し、チャンクごとにオンメモリソートして一時ファイルに書き出す。 | `tempfile.NamedTemporaryFile` |
| **K-way マージ** | 退避した複数の一時ファイルの先頭行を比較し、最小/最大のものを順次出力へ流し込む。 | `heapq.merge` |
| **カスタム重み付け** | 外部のPythonスクリプトモジュールを動的に読み込み、ソートキーの評価関数として適用する。 | `importlib` |

### 3.4 外部連携・エクスポート機能

| 機能名 | 処理内容 | 適用標準モジュール |
| --- | --- | --- |
| **SQLite永続化** | 処理後のデータを、標準のインメモリまたはファイルベースのSQLiteへ自動でテーブル定義・インポートする。 | `sqlite3` |

## 4. 非機能要件定義

* **実行環境非依存性 (Portability):**
* Python 3.x 標準ライブラリのみで動作すること。`pip install` による外部依存パッケージの追加を一切不要とする。


* **リソース制限 (Resource Bounding):**
* ファイルサイズが数GB〜数十GBに及ぶ場合でも、チャンクサイズとストリーム処理により、メモリ消費量（RAM）を常に一定（例: 500MB以下）に保つこと。


* **並列処理性能 (Concurrency):**
* 巨大ファイルのチャンク分割ソート処理など、独立した重い処理についてはマルチプロセスを活用し、処理時間を短縮すること（`concurrent.futures.ProcessPoolExecutor` の活用）。


* **保守性 (Modularity):**
* パース、抽出、ソート、出力の各責務を分離し、将来的に独自のGUIエンジン等から内部モジュールとして容易にインポート・呼び出しが可能なインターフェース設計とすること。
